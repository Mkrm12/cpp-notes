2Theory

Seven topics and a quick-fire table. The hard ones open with a Start here box: read that first. Then read the yellow "Say this" boxes out loud until they come out naturally. That's the answer you give.

2.1Pointer vs reference

Start here: the basics

The code looks worse than it is. There are only two symbols, & and *, and one rule for reading them. Four small steps.

1Every variable is a box with an address

A variable has two things: its value and its address. Writing &x asks "where does x live?". The address is just a number, printed in a strange format. You never need to know what the number is.

2A reference: a second name for the same box

The & appears once, on the line that creates ref. After that line you never write a symbol again. There is still only one box. It just has two names.

3A pointer: a separate box that holds an address

ptr on its own is an address. *ptr means "follow it". If you forget the star and write ptr = 40;, you're trying to change the address, not x, and it won't compile.

4The one rule for reading & and *

Next to a type (int, string…), the symbol says what the new variable is. Anywhere else, it does something.

You seeNext to a type?Read it as
int& ref = x;Yesref is a reference: another name for x
int* ptr = &x;Yesptr is a pointer: it holds an address
&xNoGet the address of x
*ptrNoFollow the address to the value
ptr->nameNoFollow the address, then take name. Same as (*ptr).name

Which one will you actually write? References, nearly always: every coding problem takes const string& s or const vector<int>& v. Pointers show up in two places on this page: with new (2.3) and as Animal* (gate 3B).

Check yourself

1. What does this print? Go line by line and keep track of a and b on paper.

Reveal answer

Prints 2 1 2.

  • r = 7; → r is another name for a, so a is 7.
  • *p = 1; → p holds b's address, so b is 1.
  • p = &a; → no star, so this changes the address: p now points at a. (A pointer can be re-pointed. A reference can't.)
  • *p = 2; → follow p to a, so a is 2. And r is a, so r is 2 too.

2. Say it: what does & mean in int& r = a;, and what does it mean in p = &a;?

Reveal answer

In the first it's next to a type, so it means "r is a reference". In the second it isn't, so it means "get the address of a".

3. Say it: name two things a pointer can do that a reference can't.

Reveal answer

It can be null (point at nothing, nullptr), and it can be re-pointed at something else later. A reference must be attached to a variable when it's created and stays attached for good.

Now the interview version. It's those four steps in one breath:

"A reference is an alias, another name for an existing variable. It must be set when it's created, it can't be null, and it can't be changed to refer to something else. A pointer is a variable that stores a memory address. It can be null, it can be re-pointed, and you use * to get at the value. I use references by default, especially for function parameters, and pointers when something might be null or needs to change what it points at."

That program prints four addresses. &x, &ref and ptr all come out the same, and &ptr comes out different, because the pointer is its own box.

2.2Pass by value vs reference vs const reference

Start here: the basics

Do you need this? Yes. Every coding problem on this page takes const string& s or const vector<int>& v, and "pass by value vs reference" is one of the most likely theory questions. It builds up in three small steps.

1By value: the function gets a copy

This is the default. x is a brand-new variable that starts as a copy of a. Whatever the function does to x, a is untouched.

2Add &: by reference, no copy

int& x means "x is another name for whatever was passed in". Nothing is copied, and changes go straight to the original.

3Add const: no copy, and read-only

Why bother? Copying a long string or a big vector costs time and memory. The & skips the copy, and const promises the function won't change the original. So for anything you only read, write const Type&.

You want to…Write
Use a small value: int, double, char, boolint n
Change the caller's variableint& x
Read a string, vector or object without copying itconst string& s

Rule for the coding problems: int n for numbers, const string& s for text, const vector<int>& v for lists. That covers every problem on this page.

Now the interview version, built on those three steps:

"Pass by value copies the argument, so changes inside the function don't affect the original. Pass by reference passes the original itself, so changes do affect it and nothing is copied. For big things like strings and vectors that I only need to read, I use const&: no copy, and the compiler stops me changing it by accident."

2.3Stack vs heap

"The stack holds local variables and function calls. It's fast, automatic and limited in size: when a function ends at its closing brace, everything it put on the stack is freed. The heap is a big pool for memory you ask for at runtime with new. Use it when you don't know the size in advance or the data has to outlive the function. It's slower and it isn't freed automatically: you have to delete it, or use a smart pointer that does it for you."

  • Memory leak: you new something and never delete it. On a server that runs 24/7 (like Amadeus), small leaks pile up until it crashes.
  • Dangling pointer: a pointer to memory that's already been freed, for example returning the address of a local variable (see trap 7).
  • Don't mix up the names: "the stack" (memory) is not the same as std::stack (the data structure). Both are LIFO, because function calls pile up and get popped off.

2.4RAII and smart pointers

"RAII stands for Resource Acquisition Is Initialization. You tie a resource to an object: the constructor acquires it and the destructor releases it. When the object goes out of scope, even because of an exception, the cleanup happens automatically. Smart pointers are RAII for heap memory. unique_ptr has one owner and deletes the memory when it goes out of scope. shared_ptr can have many owners, keeps a count, and deletes when the count hits zero."

That's enough. For weak_ptr, just know it exists to break shared_ptr cycles.

2.5OOP: the 4 pillars

One line each, then the example if they ask for one.

EEncapsulation

"Bundling data and the functions that use it into a class, and hiding the data with private, so it can only be changed through controlled public functions."

E.g. a bank balance is private; you can only deposit(), which rejects negative amounts.

AAbstraction

"Showing only what the user needs and hiding how it works."

E.g. you call car.start() without knowing how the engine works.

IInheritance

"A child class gets the data and functions of a parent class, so you reuse code."

E.g. Dog and Cat both inherit name from Animal.

PPolymorphism

"The same function call does different things depending on the object."

E.g. speak() on a Dog says Woof; on a Cat it says Meow.

Overloading vs overriding (a common follow-up):

Overloading

Same function name, different parameters, in the same class. Picked at compile time.

add(int, int) and add(double, double)

Overriding

A child redefines a parent's virtual function with the same signature. Picked at runtime.

Dog::speak() replaces Animal::speak()

virtual marks a function so that, when it's called through a parent pointer or reference, C++ runs the child's version. Without it, the parent's version runs. New to virtual? Gate 3B builds it up in four small steps.

If they ask about abstract classes: "A class with a pure virtual function, virtual void f() = 0;. You can't create objects of it, and children must implement that function. It's C++'s version of a Java interface."

A · Encapsulation: a class with private data

Start here: the basics

Classes look odd until you see why each piece is there. This builds the BankAccount class in four steps, adding one idea at a time.

1A class is a blueprint. An object is one thing built from it.

You already write int x;, where int is the type and x is the variable. This is the same thing: Account is a type that you made, and a is a variable of that type. The dot reaches inside an object.

2The problem with public

public: means any code, anywhere, can read and change what's below it. For a bank balance that's a bug waiting to happen.

3private locks the data. Public functions are the door.

A label like private: or public: covers everything below it, until the next label. The habit to copy: data private, functions public. Now the only way to change the balance is through deposit(), and deposit() checks the amount first. That is encapsulation.

4The constructor gives it a starting value

In step 3 nobody ever said what the balance starts at, so it holds a garbage number. A constructor fixes that.

Three ways to spot a constructor: it has the same name as the class, it has no return type (not even void), and you never call it yourself. It runs once, automatically, on the line that creates the object.

Who can use what? This is a common spoken question.

"Public members can be used from anywhere. Private members can only be used by the class's own functions. Protected is like private, except child classes can use it too. I keep the data private and make the functions public, so the class controls how its own data changes."

B · Inheritance and polymorphism: parent and child

Start here: the basics

Do you need this? Yes, but only this much. Polymorphism is one of the 4 OOP pillars, and virtual is the keyword that makes it work in C++. You need to know what it does and be able to write the Animal/Dog example. Four small steps:

1Inheritance: the child gets the parent's stuff

Read class Dog : public Animal as "a Dog is an Animal". Everything public in Animal now works on a Dog too.

2Overriding, and the catch

Now both classes have their own speak(). Calling it on the Dog itself works. Calling it through an Animal* pointer runs the wrong one:

Without virtual, C++ picks the function from the pointer's type (Animal*), not from what the object really is (a Dog).

3Add virtual: the fix

Two words change: virtual on the parent's function, and override on the child's.

Now C++ checks the real object while the program runs, and calls Dog's speak(). That's polymorphism: the same call, p->speak(), does different things depending on what the object really is.

One list and one loop handle every kind of animal. Add a Cow class later and this loop doesn't change.

3Four loop shapes solve nearly everything

The loop line is the same every time. What changes is what you set up before it and what you do inside it.

1 · Add up or count

Sum, average, count the vowels.

2 · Find the best

Biggest, smallest.

3 · Build an answer

Reverse a string, decimal to binary.

4 · Check, and stop early

Palindrome, prime, "are they all positive?". One bad element is enough for false, so return true; goes after the loop.

GROUP BY department sorts the rows into piles, one pile per department. COUNT(*) then counts the rows in each pile, so you get one row per pile. The other pile functions are SUM, AVG, MAX and MIN. Whenever a question says "per department" or "for each", it's GROUP BY.

Spoken one-liners

  • WHERE vs HAVING: WHERE filters rows before grouping; HAVING filters groups after GROUP BY.
  • DELETE vs TRUNCATE vs DROP: DELETE removes chosen rows (it can use WHERE). TRUNCATE removes every row, fast, but keeps the table. DROP deletes the whole table, structure included.
  • Normalisation: splitting data into linked tables so the same thing isn't stored twice.

This is half the score. Run through these six steps for every coding question.

⏱Setup, 10 minutes before: open the online compiler with the starter template already pasted in, and zoom in so they can read your screen share. Close everything else.

  1. Repeat it backSo I'm given ___ and need to return ___?
  2. Ask one edge caseWhat if it's empty? Upper and lower case?
  3. Say the plan before typingI'll loop through and ___, which is O(n).
  4. Talk while you typeThis is my loop over every character… this checks whether…
  5. Dry runWalk a tiny example through your code out loud before pressing Run.
  6. If it errors, stay calmRead the line number out loud and fix it. That's fine; they want to see it.
