1Classes and objects

The first question in almost every OOP interview.

A class is a blueprint. An object is a real thing built from that blueprint. The class says what data each object holds and what it can do. Each object gets its own copy of the data.

2Constructors and methods

Two kinds of function that live inside a class.

A constructor is a special function that runs automatically when an object is created. It has the same name as the class and no return type, and its job is to give the variables their starting values. A method is a function that belongs to a class and works on that object's data.
private:Only the class's own functions can touch what comes after it.
public:Anyone can use what comes after it.
GetterA method that just hands back a private variable, like getName().

The six traps

The first five stop it compiling. The last one compiles, then shows nothing.

  1. A class ends with a curly bracket and a semicolon.class Student { ... }class Student { ... };
  2. Every variable needs a type in front.age;int age;
  3. The constructor has the class's name and no return type.void Student(string n, int a)Student(string n, int a)
  4. Make an object like a variable: type, name, then the starting values.s1 = Student("Aisha", 21);Student s1("Aisha", 21);

    The first line is how Python does it. C++ wants the type first.

  5. Text needs double quotes.Student s1('Aisha', 21);Student s1("Aisha", 21);
  6. To show something on screen, use cout.return name;cout << s1.getName() << endl;

    return hands a value back to whoever called the function. It doesn't print anything.

4Static vs non-static

Who owns the variable: each object, or the class?

A non-static variable belongs to each object, so every object has its own copy. A static variable belongs to the class itself, so there is one copy shared by all the objects. A static method can be called on the class without creating an object, and it can only use static data.
i

Picture it. Every student has their own name (non-static). The school has one head count (static). Change the head count and everyone sees the new number.

5Abstract class vs interface

Start with one idea: a pure virtual function is a function with no code, written = 0. It means "every child class must write its own version of this".

An abstract class is a class with at least one pure virtual function. You can't create an object from it; you can only inherit from it. It can still have normal functions and data that the children share. An interface is the strict version: only pure virtual functions, no data and no code. It's a contract that says what a class must be able to do, not how. C++ has no interface keyword, so you write one as a class with only pure virtual functions.

6Stack vs heap

Two places a program keeps its data.

The stack holds local variables. It's fast and it cleans itself up when the function ends. The heap is memory I ask for with new. It stays until I delete it, so if I forget, that's a memory leak. Smart pointers delete it for me.

7Data structures and speed

"Time complexity" means: how much slower does it get when there is more data? Three speeds cover almost everything.

WrittenSaidMeans
O(1)"constant"Same speed however much data there is. One step.
O(log n)"log n"Halves the problem each step. A million items takes about 20 steps.
O(n)"linear"Might have to look at every item. Twice the data, twice the time.

An array gives me any item by its index in constant time, but searching it is linear. A linked list is the opposite: cheap to insert, slow to reach a position. A hash map or set finds things in constant time on average, which is why I use one when I need fast lookups. The sorted map and set are log n, and I'd pick those when I need the data in order.

8Dictionary and set

Both find things fast. One stores pairs, the other stores single values.

A dictionary stores pairs: a key and a value. I give it the key and get the value back fast. In C++ that's unordered_map. A set stores only keys, no values, and never holds the same thing twice. I use a dictionary to look something up, and a set to remove duplicates or to check whether I've seen something before.

Why is the lookup fast?

It turns the key into a number (a "hash") that says which slot to look in. So it jumps straight to the right place instead of searching. That is the O(1).

9Two-minute self test

Say each answer out loud first, in one or two sentences. Then tap to check.

What's the difference between a class and an object?

A class is the blueprint. An object is one real thing built from it. One class can make many objects, and each has its own data.

What is a constructor, and how do you recognise one?

A function that runs automatically when an object is created and gives the variables their starting values. It has the same name as the class and no return type.

What is a method?

A function that belongs to a class and works on that object's data.

Why make variables private?

So code outside the class can't change them by accident or set them to something that makes no sense. Outside code has to go through the public methods, and the class controls those.

Static variable vs non-static variable?

Non-static: every object has its own copy. Static: one copy that belongs to the class and is shared by every object.

Abstract class vs interface?

You can't make an object from either. An abstract class has at least one pure virtual function but can also hold data and normal functions. An interface has only pure virtual functions: it is a contract, with no code.

Stack vs heap?

The stack holds local variables and cleans itself up when the function ends. The heap is memory you ask for with new, and it stays until you delete it.

Array vs linked list: which is fast at what?

An array gets any item by its index in O(1), but inserting in the middle is O(n). A linked list inserts or removes in O(1) where you already are, but reaching item number i is O(n).

Why is a dictionary lookup fast, and what's its time complexity?

It hashes the key into a slot number and jumps straight to that slot, with no searching. O(1) on average.

Dictionary vs set?

A dictionary stores key and value pairs, and you look a value up by its key. A set stores only unique values: use it to remove duplicates or to check "have I seen this?".
